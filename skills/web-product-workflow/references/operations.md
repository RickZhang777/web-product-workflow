# 经营与数据

<a id="benchmarks"></a>
## 竞品证据

先按目标客户、核心任务、地区及发展阶段选可比产品。可优先查三到五个，按可核证据收敛。平台型产品可供功能观察，核心对标选可以比较业务与流量结构的站点。

D 记录目标域名、统计期、来源与指标定义。核官网定位、定价、核心功能、搜索词、SEO 页面及主要流量来源，用已有工具交叉验证。工具面板需确认实际查询对象，统计期和口径不同的结果分开写。缺数据标未知。QA 逐一复核拟入选的域名、统计期、来源与可比性，有足够证据的站点才列入正式对标。

<a id="pricing"></a>
## 套餐和成本

PM 定义客户可获得的价值和使用权益，D 按实际调用与交付成本估算可行性，ENG 落实服务端校验。选订阅、点数或单次收费时，根据使用频次与成本决定。使用 Free、Plus、Pro 时，写清三档各自权益、升级与降级的生效时间和额度处理。免费体验能验证核心价值，也要有单用户与全站成本边界。

需要接支付时核地区与业务资格、费用、到账条件和退款能力。测试支付、真实收款和到账分栏。对可能重试的支付和额度操作核幂等，失败按已定规则结算。发布前用对应版本验证成功、拒绝、重放和变更权益的结果。

<a id="experiments"></a>
## 获客实验

G 先选客群最集中的一个渠道，再定承接页和期望动作。实验记录客户与渠道、假设、动作、指标、总预算、观察期和停止条件。投入以当前项目获准的累计上限为准。预算小或样本稀疏时，先做顺序验证并说明局限。只在已有授权范围内调配，新增投入由用户决定。

<a id="metrics"></a>
## 指标与复盘

D 把来源、访问、核心任务成功、首付、续费、退款与可变成本串起来。用现有分析工具记访问来源，用服务端业务事件记成功与失败，用账本核收款和成本。维度至少注明时间范围、币种、来源及测试状态。站外估算和站内实测分别记录。

复盘找对客户价值或贡献最大的一个瓶颈。先核数据完整性、样本量和转化回传延迟，再提出下一项验证。获客成本和贡献按可对账数据算，说明采用的分母、费用和观察窗口。缺测和未成熟数据保留原状态。

<a id="portfolio"></a>
## 多站取舍

多站经营可共用一名组合分析负责人，读取各站 D 的同口径底稿。日报列异常和需行动的事项。周报按站列成功使用、付费、广告与交付成本、数据缺口以及加投、观察、修复或止损建议。每项建议附依据和下一复盘点，由用户决定，交各站 O 接手。
