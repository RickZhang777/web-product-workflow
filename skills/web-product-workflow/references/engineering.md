# 工程与验收

[English](en/engineering.md) · **简体中文**

<a id="bootstrap"></a>
## 接手仓库

ENG 读项目规则、相关代码、依赖清单、锁文件和环境变量样例，记录可运行的基线。把登录、数据库、计费、存储等能力区分为可复用、需适配和待新增。以仓库配置确定包管理器、模块格式和部署目标。依赖或环境变量有变化时记录用途、变量名和适用环境。所需凭证由用户放入环境配置或秘密管理服务。

<a id="changes"></a>
## 实现与变更

用最简单的实现满足已知需求。每个函数承担一件明确的事，多步操作由主函数调度。拆分时保留事务、幂等和重试边界。先复用现有模块和工具，出现重复用例后再判断是否需要抽象。

影响到共享流程时，在现有 SPEC 标明相关功能 ID、入口、接口或数据、业务约束、代码位置和验证方式。开工前回答改什么、影响哪里、必须保持什么、怎样验。小改动只更新受影响部分。

支付、权限、额度与关键数据写入要有对应反例。模型、网络和数据操作失败时按业务语义暴露真实状态，避免错误计费或把样例记作成功。承诺流式体验时验证结果会在请求完成前增量显示。破坏性数据操作先核目标、权限与预期影响范围。

<a id="qa"></a>
## 独立验收

ENG 交改动范围、代码与配置版本、自测和未测项。QA 针对同一版本，检查用户能否找到入口、完成核心任务、理解等待与错误反馈并恢复。按改动核关键异常、数据归属、重复请求、关联功能与费用。用可用浏览器或等效方式实测，静态检查用于补充证据。

验收记录含版本、环境、操作或命令、实际结果及结论。把通过、失败和未测分开。关键失败退 ENG 修复，相关改动用新版本复验。缺独立检查者时保留待验收状态。

<a id="release"></a>
## 外传与上线

外发前确认目标、授权和实际范围。用现有检查入口扫描待上传文件与待推提交，检查凭证、个人信息及内部资料。部署前核对应构建产物和接口响应，避免秘密通过客户端包、序列化、日志或错误信息暴露。公开示例使用虚构内容或明确允许公开的材料。

验收以实际扫描范围、目标版本和结果为准。敏感命中未处理、关键检查异常或证据与版本不符时暂停对应动作。能确定判定的规则可用现有 CI 或 Hook 自动化，QA 核验实际生效范围。获准发布后，ENG 保留回滚途径，QA 复验目标环境的核心流程。

<a id="feedback"></a>
## 反馈闭环

收到反馈后，按症状和功能归类、去重并保留可复现的最少证据。产品问题归 PM，故障归 ENG，分析归 D，O 负责接手和优先级。改动经过[独立验收](#qa)后再更新工单和对外结果。需要自动修复时，先设允许范围、重试与花费上限，在隔离环境验证对应动作。
